- **CVE-2026-76642 — vulnerable_code_not_in_execute_path.** Mount helper/post-hook privilege escalation requires privileged mount execution. The candidate removes mount/umount; operations never call libmount. The serving process has zero effective capabilities. Remedy: Upstream util-linux 2.41.6 or 2.42.3; Debian trixie remains affected. [Debian advisory](https://security-tracker.debian.org/tracker/CVE-2026-76642).

- **CVE-2026-78408 — vulnerable_code_not_present.** The flawed nsenter executable is removed. Operations never invoke nsenter or accept an inherited root-opened cgroup migration descriptor. Container PID/cgroup namespaces and mounts stay isolated. Remedy: Upstream advisory lists 2.41.6/2.42.3; Debian additionally references commit 286dd3ff41526b582ef48830de239dffbaa61f90 in 2.42.4. Use the Debian fixed revision when available. [Debian advisory](https://security-tracker.debian.org/tracker/CVE-2026-78408).

- **CVE-2026-78409 — vulnerable_code_not_in_execute_path.** The candidate removes mount and exposes no libmount API. The exploit needs a privileged fstab-authorized X-mount.subdir path, attacker-controlled source and Linux >=6.15. Upstream lists >=2.42 while Debian flags 2.41.5; retain the distro finding and resolve by missing path. Remedy: Upstream 2.41.6/2.42.3; vendor affected-range conflict retained explicitly. [Debian advisory](https://security-tracker.debian.org/tracker/CVE-2026-78409).

- **CVE-2026-78410 — vulnerable_code_not_in_execute_path.** Restricted bind-mount pathname replacement needs privileged mount plus fstab X-mount.owner/group/mode hooks. The candidate removes mount and umount; trusted operations never execute this path. Remedy: Upstream 2.41.6/2.42.3; Debian trixie remains affected. [Debian advisory](https://security-tracker.debian.org/tracker/CVE-2026-78410).

- **CVE-2026-54369 — vulnerable_code_not_in_execute_path.** libacl1 remains installed for OS compatibility. Python operations use SQLite backup, byte copy, chown and chmod on fixed private paths; they never call acl_*_file APIs or launch ACL-preserving utilities. Node serves as UID1000 with zero capabilities. Root init-volumes performs only fixed-path chown/chmod/makedirs, without ACL calls or untrusted requests. Remedy: acl 2.4.0 adds new *_at ABI; Debian schedules a point-release fix and warns individual backports/ABI conflicts. Prefer the Debian package over replacing libacl ad hoc. [Debian advisory](https://security-tracker.debian.org/tracker/CVE-2026-54369).

- **CVE-2025-69720 — vulnerable_code_not_present.** The vulnerable analyze_string implementation belongs to infocmp. The candidate removes that executable. Retained ncurses libraries/terminfo data do not contain that command implementation. Remedy: Upstream ncurses 6.5-20251213; Debian fixed source 6.6+20251231-1, with no trixie fix at review. [Debian advisory](https://security-tracker.debian.org/tracker/CVE-2025-69720).

- **CVE-2026-15308 — vulnerable_code_not_in_execute_path.** Repeated incremental HTMLParser.feed on hostile declarations causes the flaw. ops.py and its loaded import closure contain no html parser. Browser HTML uses browser/JavaScript paths. Python reads local JSON/SQLite/files only. Remedy: CPython 3.13.15 (commit 7933f4bf7131aa4140750f9404f5de0aa2969ced); Debian trixie 3.13.5-2+deb13u5 remains affected. [Debian advisory](https://security-tracker.debian.org/tracker/CVE-2026-15308).

- **CVE-2026-19445 — vulnerable_code_not_in_execute_path.** Python never imports ssl/_ssl or opens a TLS server, and defines no SNI callback/context switch. Caddy terminates TLS; app communication uses Unix sockets. Network-none reinforces this separate code-path evidence. Remedy: CPython 3.13.16 fix d8717ed01717a9641686e6e6f83f0ab8af235e2c; Debian trixie remains affected. [Debian advisory](https://security-tracker.debian.org/tracker/CVE-2026-19445).

- **CVE-2026-19553 — vulnerable_code_not_in_execute_path.** Python never imports ssl/asyncio or calls wrap_bio, create_connection or start_tls.
